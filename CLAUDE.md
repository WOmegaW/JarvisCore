# CLAUDE.md — память проекта MixAlmacén

Читается автоматически в начале каждой сессии. Держать коротким и правдивым; при изменении
архитектуры или после нового «подводного камня» — обновлять этот файл.

## Что это и для кого

Telegram-бот + мини-приложение для учёта сроков годности в продуктовом магазине
**MixAlmacén** (Торремолинос, **Испания**). Бот: **@mixalmacen_bot**. Работает в группе
из 5 сотрудников. Сотрудник вносит товар (фото, штрихкод, срок, количество) — бот:
- **за 2 дня до конца срока** напоминает поставить **скидку 50%** (всегда ровно 2 дня и 50%,
  для всех товаров, разных сроков по отделам НЕ нужно — так решил владелец);
- **в день окончания срока** напоминает **списать**;
- каждое утро присылает сводку просроченного, но не отмеченного.

## Как общаться с владельцем

- Пишет и читает **по-русски**, не программист. Работает с **iPhone** (иногда с компьютера).
- Давать **готовые команды для копирования**, по одной, с объяснением «куда нажать».
  Длинные действия — пронумерованными шагами. Просить скриншот при любой ошибке.
- Честно говорить, что проверено (тестами), а что нет (на живом телефоне/сервере).
- Отказался ставить сторонний набор `everything-claude-code` — не предлагать снова.

## Архитектура

```
Telegram ──webhook──► PythonAnywhere: flask_app.py (/webhook, /app, /api/*)
                         ├─ bot/handlers.py   — команды и шаги /add в чате (aiogram 3)
                         ├─ bot/webapp.py     — API мини-приложения + раздача webapp/
                         ├─ bot/notifier.py   — напоминания (скидка / списание / сводка)
                         └─ data/expiry.db    — SQLite (товары, журнал events, шаги диалога fsm)
cron-job.org (аккаунт владельца), каждый день 09:00 Europe/Madrid ──► POST /__daily?part=plan
   (заголовок X-Deploy-Secret) ──► напоминания по партиям + «☀️ План на день» в группу. ГЛАВНЫЙ будильник:
   точный, сам учитывает летнее время; part=plan — без резервной копии, чтобы уложиться в 30 с.
GitHub Actions morning.yml (07:07, 08:07, 08:37 UTC) ──► POST /__daily — запасной + резервная копия:
   GitHub может опоздать на 10+ часов (26.11.2026 «утренний» запуск пришёл в 18:39).
   План — ровно раз в день (флаг morning_last_day) и только в окне 09:00–12:00 по Мадриду;
   опоздавшие запуски шлют лишь напоминания по партиям и копию.
⚠️ На бесплатном PythonAnywhere задания по расписанию (Tasks) НЕДОСТУПНЫ (API: «Scheduled tasks are
   not available on free accounts», 26.11.2026) — `bot.daily` годится только для платного тарифа/VPS.

Запасной путь (готов, ждёт доступа): Telegram Serverless (miniapp/)
  телефон ─► app<id>.tgcloud.ai (страница) ─► endpoint relay ─► PythonAnywhere /api/*
```

## Модель данных: карточка = штрихкод, строка `products` = партия

**Количество НЕ ведём** (решение владельца, 27.11.2026): вносят фото + штрихкод + срок; тот же товар
с другим сроком — ещё одна партия. «Продано» / «Списать» закрывают партию целиком. Колонки
`quantity`/`initial_qty`/`sold_qty`/`written_off_qty` в базе остались (всегда 1 / история),
но в интерфейсе, сообщениях и плане штук нет. Миграция `qty_removed_v1` один раз ставит 1 шт.
всему, что на полке (и в базе из старой резервной копии).

В базе каждая строка `products` — **партия** (свой срок, количество, статус, напоминания).
В мини-приложении партии с одним штрихкодом склеиваются в **одну карточку** (`buildCards`):
в списке — самый срочный срок, «N сроков: дд.мм · дд.мм»; в карточке — список
партий, у каждой свои кнопки (скидка / продано / списать / изменить / удалить) и
«Добавить новый срок» (штрихкод, название и фото подставляются). В форме добавления —
кнопка «＋ Ещё срок»: несколько дат за раз → `POST /api/products` с `expiries: [...]` создаёт по
партии на дату (одно фото, одно сообщение в группу; повтор даты не дублируется). Название и новое фото,
изменённые в любой партии, применяются ко всем открытым партиям штрихкода
(`db.share_card_info`). Напоминания бота — по партиям (у них разные даты).

## Подводные камни (уже наступали — не повторять)

0. **Утренние сообщения не приходили** (ноябрь 2026): утреннего плана не было вовсе (только
   напоминания при добавлении + сводка просроченного), а запуск держался на одном задании
   PythonAnywhere (07:00 UTC = 8:00, бесплатные задания надо продлевать). Потом GitHub-расписание
   опоздало на 10 ч и «Доброе утро» пришло в 18:39 → окно 9–12. Задания PythonAnywhere на бесплатном
   тарифе нет вовсе → главный будильник — cron-job.org (настраивает владелец, см. README).
   `/__daily` и `/__deploy` защищены одним секретом `DEPLOY_SECRET`.

1. **Прокси PythonAnywhere.** Бесплатный тариф выпускает в интернет только через
   `http://proxy.server:3128`. **aiohttp через него получает 503** (и с aiohttp-socks тоже),
   а `curl`/`urllib` работают → поэтому `bot/http_session.py` на urllib. Прокси иногда
   **на секунду отвечает 503** на CONNECT → повтор до 4 раз; **Request создавать заново на
   каждую попытку** (urllib портит объект запроса при работе через прокси).
2. **Сообщение в группу — не часть действия.** Если не ушло уведомление «Аня отметила
   продажу», действие всё равно успешно (`announce()` глотает ошибку). Раньше это давало
   500 при уже записанной продаже. Добавление товара — наоборот: без отправки фото товар
   откатывается (нужен file_id для напоминаний).
3. **После ошибки фронтенд перезагружает состояние** (`refreshAfterError`) — иначе на
   экране остаётся закрытый товар.
4. **Испания:** часовой пояс `Europe/Madrid` (была ошибка с Москвой — даты съезжали после 22:00).
   Задание PythonAnywhere в UTC: 07:00 UTC = 08:00 зимой / 09:00 летом.
5. **С мобильного интернета сайт PythonAnywhere бывает недоступен** (в Испании операторы во
   время матчей LaLiga блокируют IP хостингов). Бот в чате работает всегда (через Telegram).
   Решение — Telegram Serverless (`miniapp/`), но бот **в листе ожидания** Serverless
   (BotFather → Serverless → «You're on the waitlist»). Когда дадут доступ: секреты GitHub
   `TGCLOUD_TOKEN` (BotFather → Serverless → CLI Access) и `FORWARD_SECRET` (= `WEBHOOK_SECRET`
   из `.env`), запустить workflow, вписать адрес `https://app<id>.tgcloud.ai/` в BotFather.
   У Serverless **нет таймера** — напоминания остаются на PythonAnywhere.
6. **Group Privacy у бота выключен** — иначе бот не видит фото и ответы в группе.
7. Количество `0` — ошибка, а не «1 шт.» (было `int(x or 1)`).
8. В тестах Telegram-сообщение с `date: 0` aiogram считает «недоступным» — брать реальную дату.
10. **Telegram на iPhone сворачивает мини-приложение, а не закрывает** — при повторном открытии
   показывает старую страницу из памяти (после обновления у владельца осталось поле «Количество»).
   Теперь `/app` вшивает версию кода (`__APP_VERSION__` → коммит), `/api/state` отдаёт `app_version`,
   и страница при расхождении сама делает `location.reload()` (не на экране формы).
9. initData мини-приложения проверяется на сервере (подпись + членство в группе через
   `getChatMember` + срок 24 ч). Ссылка на приложение: `https://t.me/mixalmacen_bot?startapp=<id группы>`.

## Резервные копии (важно для владельца: 1000+ товаров нельзя потерять)

- Владелец один раз пишет боту в **личный чат** `/backup_here` → id чата в таблице `settings`.
- Каждое утро `bot.daily` присылает туда zip (тихо, без звука): база + таблица для Excel + фото
  (уменьшенные до 480px, лимит архива 45 МБ). Telegram хранит файлы бессрочно — копия не
  зависит от PythonAnywhere (бесплатный аккаунт удаляют после ~3 мес. без входа!).
- `/backup` — копия сейчас (докачивает не более 40 недостающих фото за раз, остальное — ночью).
- Восстановление: загрузить zip в `~/JarvisCore` (Files → Upload) →
  `~/venv/bin/python -m bot.restore <архив.zip>` → Web → Reload. Прежняя база сохраняется рядом.
- Фото есть и в самой группе (карточка каждого добавленного товара), а `photo_file_id` в базе
  действуют, пока жив токен бота.

## Как бот обновляется на сервере

**Автоматически** (после настройки секретов): push в ветку → GitHub Actions `tests.yml` →
если pytest и браузерные тесты зелёные, job `deploy`: `POST /__deploy` (секрет `DEPLOY_SECRET`,
сервер делает `git pull --ff-only` + `pip install` при изменении requirements.txt, см.
`bot/deploy.py`) → API PythonAnywhere `…/webapps/carbonara.pythonanywhere.com/reload/`
(секрет `PA_API_TOKEN`) → проверка `/version` == новый коммит.
Секреты GitHub: `DEPLOY_SECRET` (= `DEPLOY_SECRET` в `~/JarvisCore/.env`), `PA_API_TOKEN`
(PythonAnywhere → Account → API token). Без секретов job просто пропускается.
Если сервер правили руками (`git status` грязный) — автообновление остановится, чтобы не
затереть правки. `bot.daily` запускается заново каждый раз, ему перезапуск не нужен.

**Вручную** (если автообновление не настроено или сломалось):
```
cd ~/JarvisCore && git pull && ~/venv/bin/pip install -r requirements.txt
```
затем PythonAnywhere → **Web → Reload**; приложение в Telegram закрыть и открыть заново.

## Тесты — запускать перед каждым коммитом

```
pip install -r requirements-dev.txt
python -m pytest                                  # бот, API, база, прокси (~3 с)
cd tests/e2e && npm install && npx playwright install chromium && npm test   # браузер (~15 с)
```
В облачной сессии Claude Chromium уже есть: `cd tests/e2e && NODE_PATH=$(npm root -g) npm test`
(не делать `playwright install`). GitHub Actions (`.github/workflows/tests.yml`) гоняет оба набора
на каждый push. Новую функцию — сразу с тестом; найденную ошибку — сначала воспроизвести тестом.
